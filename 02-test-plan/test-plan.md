# Тест-план
**Проект:** QA Pet Project
**Автор:** DARI
**Дата создания:** 2026-09-20
## 1. Введение

Данный тест-план описывает стратегию, объём, ресурсы и расписание
тестирования веб-приложения SauceDemo и API Swagger.

Цель — продемонстрировать навыки ручного тестировщика: планирование,
документирование, поиск дефектов, оформление отчётности.
## 2. Объект тестирования

SauceDemo веб-приложение https://www.saucedemo.com

API Swagger https://api.qasandbox.org/swagger/#/Auth/post_register

**Браузеры:** Chrome, Yandex

**ОС:** Windows 11
## 3. Объём тестирования

### 3.1. Входит в тестирование
- Функциональное тестирование модулей SauceDemo:
  авторизация, каталог, корзина, checkout, сортировка, меню.
- UI-тестирование (вёрстка, элементы, сообщения об ошибках).
- Кросс-браузерное тестирование (Chrome, Yandex).
- Тестирование API Swagger в Postman.
- Негативные сценарии (пустые поля, неверные данные, граничные значения).
- Базовые проверки безопасности.

### 3.2. Не входит в тестирование
- Автоматизация (проект ручной).
- Нагрузочное тестирование.
- Тестирование backend-инфраструктуры.
- Локализация (кроме проверки текстов на английском).

## 4. Стратегия тестирования

### 4.1. Виды тестирования

1.Функциональное-проверка бизнес-логики модулей
2.UI/UX-верстка, элементы, сообщения
3.Кросс-браузерное-chrome, yandex
4.API-postman, коды
5.Негативное-ошибочные сценарии
6.Безопасность

### 4.2. Подходы
- **Исследовательское тестирование** — свободное изучение продукта.
- **Тестирование по чек-листам** — систематическая проверка.
- **Тестирование по тест-кейсам** — формальные сценарии.

### 4.3. Уровни тестирования
- Компонентное (отдельные элементы).
- Интеграционное (модули вместе: корзина + checkout).
- Системное (весь продукт).
- Приёмочное (симуляция пользователя).

## 5. Критерии начала и окончания

### 5.1. Критерии начала
- Анализ требований завершён.
- Тестовое окружение готово (браузеры, Postman).
- Тестовые данные известны (логины SauceDemo).
- Чек-листы и тест-кейсы подготовлены.

### 5.2. Критерии окончания
- Все запланированные тест-кейсы выполнены (100%).
- Не менее 90% тест-кейсов в статусе Passed.
- Все критичные (Critical/Blocker) баги задокументированы.
- Итоговый отчёт о тестировании составлен.
- Баг-репорты оформлены и загружены на GitHub.

## 6. Тестовое окружение и инструменты

### 6.1. Окружение
- **ОС:** Windows 11 (22H2)
- **Браузеры:** Chrome, Yandex
- **API-клиент:** Postman 10.x

### 6.2. Инструменты

- **Chrome DevTools** анализ запросов, консоль, вёрстка
- **Postman** тестирование API
- **Github** хранение документации
- **SQLite Online** выполнение SQL-запросов

- Валидный username: "hercules_77"

- Логин: 1 символ / 40 символов / пусто
- Пароль: 1 символ / 40 символов / пусто
